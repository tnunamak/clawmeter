## Ranked divergences that break the rule

1. **Freshness changes the meaning and selection of quota facts.**  
   `internal/cli/status.go:284–285,951–955,991–1003` and `internal/tray/tray.go:2077–2083,2176–2185` recompute forecasts/run-out or risk from last-good windows even when `UsageData.Stale` is true. Meanwhile `--agent` replaces their projection with `{Stale:true, Unknown:true, WillLastToReset:true}` at C549–550; tooltip/icon suppress it at T1935–1940/1767–1768. CLI selection also ranks stale providers using their unmasked maximum projection before masking the selected windows (C1471–1499,791–797), whereas the icon explicitly prefers any fresh reset-backed quota (T1542–1547). Thus a stale critical source can headline agent/statusline while the tray selects a fresh healthy source.  
   **Fix:** derive freshness-aware projections and selection once; stale observations must not establish current exhaustion or projected blocking.

2. **Known exhaustion and unknown-reset semantics are inconsistent.**  
   A fresh 100%-used window during forecast warm-up gets `"out now"` in the menu/table (`internal/meter/meter.go:211–218`), but `forecast.Project` returns unknown with `WillLastToReset:true` (F129–134), so plain/tooltip/agent omit out-now. Statusline also omits out-now for an ordinary exhausted, forecastable window because C455 requires positive ETA. Agent always emits `reset_in=0s` for missing reset timestamps (C482–490,583–587), unlike plain `"reset not reported"`. JSON encodes unknown forecast as numeric `projected_pct:0` plus `"unknown"` (C951–955; F133–134).  
   **Fix:** share explicit `exhaustion_state`, `forecast_state`, optional forecast/reset durations, and “known exhausted” handling independent of extrapolation.

3. **Machine outputs omit facts they have ample capacity to carry.**  
   `--json` exposes only two forecast fields (C885–889), losing run-out ETA, early-by and observed out-since. `--agent` omits `NextCreditAt`, `MonthlyCredit`, dynamic sign-in/browser CTA, reset-browser refresh CTA, and individual provider errors (C687–746,619–656,466–479). JSON returns raw pool `Live`, reset `AvailableCount`, and old balance even when effective render-time state differs; Q299–324 does not evaluate `IsLive`, P462–481 dynamically derives displayed reset count, and C701–709 explicitly treats expired observed balance as unknown. These raw observations are useful, but not equivalent to current presentation facts.  
   **Fix:** preserve raw observation fields for compatibility and add shared effective freshness/count/balance-state/CTA/forecast fields. Agent should render those rather than independently reconstruct a subset.

4. **Tray expiry wording presents a projection as a definite amount.**  
   `internal/provider/creditpool.go:197` renders `ProjectedUnused` as `"$X expires …"`. Plain instead says `"on pace to spend … before it expires"` (Q175); JSON/agent distinguish actual `Expiring` from projected unused (Q33–49; C732–734).  
   **Fix:** say “est. $X unused at expiry,” or show actual expiring credits and label the forecast separately. Compactness does not justify changing projected money into an asserted fact.

5. **Out-since is a separate tray-local fact, not a shared system fact.**  
   Confirmed in **both tray menu and tooltip**, not menu only: T2093–2094/2162 and T1948/1996. `internal/tray/exhaustion.go:1,49–53,100–112,215–254` keeps it tray-build-local, account/reset-bound, and only after suitably close successful observations. Other surfaces do not read or export it. It is the first observed full reading, not a provider-confirmed exact exhaustion instant.  
   **Fix:** expose the validated observation through a shared read model/cache with provenance, keeping the identity/reset/gap safeguards. Do not fabricate the time in CLI.

6. **Source labels, ordering, and row membership are not shared.**  
   A lone named source loses its account label in tray (`internal/tray/tray.go:64–68`) but retains it in CLI (`internal/cli/status.go:1433–1436`). Tray/plain order by display name; agent by urgency; JSON groups into maps and source-ID arrays despite a comment promising urgency order (C1678–1682 versus C901,923); hub inherits source-key order. Plain places reset credits/announcement before balances/pools (C296–310), whereas tray places money first (T749–771). Window naming differs among meter codes, internal names and tooltip long labels.  
   **Fix:** share canonical display labels and explicit presentation-order arrays; preserve machine IDs separately. Treat urgency as an additional rank/selected-target fact, not an implicit incompatible ordering.

7. **Quota membership differs beyond necessary compactness.**  
   Tray/table hide idle windows (`internal/meter/meter.go:116–128`), but plain includes them (C270–272). Tray silently caps windows at eight and balances+pools at eight (T706,737,749,1195–1197,866–873). CLI has no equivalent cap. Hub drops Codex scoped windows, Claude OAuth windows and non-whitelisted names (H443–462,486–492); in-scope `internal/tray/codex_labels_test.go:12–26` explicitly describes supported scoped Codex names.  
   **Fix:** share a documented visibility policy, provide tray overflow rather than silent truncation, and explicitly label the hub as a limited projection. Extending the hub requires a client-supported contract, not silently inventing incompatible fields.

8. **Error/setup visibility loses actionable facts.**  
   Agent/statusline skip expired or error-only providers and can report only “no quota data” (C788–790,466–479,430). JSON drops a sole provider with nil data (C935–938), including some `--all` inventory entries. Tray keeps history-aware errors (`menu.everHealthy`, T1104–1114); CLI always calls the shared visibility function with prior-history=false (C379–386). The Token Plan has a tray-only setup discovery path (T1067–1077,1111–1112).  
   **Fix:** share provider states and actionable reason/next-step text; explicitly represent unavailable/setup/error entries even where quota detail is compressed.

9. **Selected-window tooltip omits current usage in the normal case.**  
   `internal/tray/tray.go:1992–2003` provides run-out, reset and estimate, but only displays current % when projection is unknown/stale. Statusline similarly normally exposes estimate, not current (C453–454). A known used-% fact is missing even for the one selected quota.  
   **Fix:** put “used X%, est. Y%” on one compact line; keep the selected summary semantically complete without listing every quota.

10. **Update availability and next-step prompts live outside the shared status model.**  
    Tray has pending release/version/dot and contextual setup actions (T475–483,1900–1906,248–294), but normal CLI status/JSON/agent have no update state; setup guidance also varies as above. These omissions are not imposed by text/JSON capacity.  
    **Fix:** add optional cached update/setup facts to the shared presentation model, without making statusline trigger network checks or update actions.

## Justified medium/adapter differences

- **One selected quota in icon, tooltip and statusline:** reasonable for glanceable surfaces. Pinning the icon is a deliberate user override, not a selection bug. The underlying identity/freshness/exhaustion semantics should still agree.
- **Graphical icon versus exact values:** 22/32px artwork cannot show every number, account, timestamp or CTA. The actual V10 renderer conveys usage versus expected pace, not numeric projected-at-reset; `RiskPct`’s old comment should not be mistaken for a third rendered channel.
- **Tooltip compactness:** four selected-quota lines, optional resets/announcement/update is intentional (T1987–2004,1952–1959). Omitting all other accounts and credit-pool detail is defensible. It does not explain inconsistent current/out-now states.
- **Click versus text:** confirmed, with an important qualification. Only API pool rows whose `Action(now)` is nonempty are enabled/clickable (T870,894); they open the Claude Console (T839–845). Live pools and ordinary balance rows remain disabled. Reset-credit rows are disabled (T763–765). Plain CLI showing the same action as text is appropriate; losing/changing the action itself is not. Tray announcement source links versus text references are similarly reasonable.
- **Precision and representation:** rounded human percentages/times, exact agent seconds, JSON absolute timestamps/minor units and protocol-specific reset timestamps are appropriate if unknown/freshness semantics remain explicit.
- **T3 compatibility restrictions:** rejecting stale/identity-unbound readings is explicitly necessary because successful hub responses are treated as current (H141–143,162–163,434–436). Codex reset-credit 404 is deliberate: IDs needed for redemption are unavailable, and an empty list would falsely mean zero (H278–282). `openai`→`codex`, `five_hour`/`primary_window`, and account email/workspace identity are protocol requirements, not arbitrary UI renaming. The current adapter is consequently a documented subset, not full isomorphism.
- **Cache-only statusline:** appropriate to avoid provider refreshes on frequent prompt renders (C1017–1024,1142–1163). Freshness labels must communicate the resulting observation age.
- **Reset announcements are annotations, not quota resets:** shared visibility suppresses stale/error readings, requires qualifying windows and bounded feed age, and preserves original quota/reset values (`internal/resetfeed/visibility.go:18–55,67–98`). Menu/plain/tooltip share the same summary; agent/JSON retain explicit unofficial provenance. No evidence that announcements alter risk or quota math.

Recommended direction: one immutable, render-time presentation snapshot containing canonical identity/order, quota facts and observation state, credit/reset effective state, selected risk target, announcements and available actions; each surface then performs only bounded formatting/projection.
